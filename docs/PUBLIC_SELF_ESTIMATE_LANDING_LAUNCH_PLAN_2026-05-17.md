# 공개용 셀프견적 랜딩 출시 계획

## 목표

기존 셀프견적 흐름과 분리된 새 퍼널을 별도 공개 랜딩으로 열고, 광고/대리점 유입을 제한적으로 받아 실제 전환 데이터를 검증한다.

## 현재 이미 있는 기반

- 문자 발송 API: `src/app/api/send-sms/route.ts`
- 고객 저장 API: `src/app/api/customers/route.ts`
- 기존 상담 제출 로직: `src/app/(customer)/submit/page.tsx`
- 기존 견적 계산 로직 및 count-up 효과: `src/app/(customer)/estimate/page.tsx`
- 새 퍼널 프로토타입: `src/app/prototype/selfest-v2/page.tsx`

## 출시 전 구현 순서

### 1. 공개 랜딩 라우트 확정

결정 필요:
- 실제 공개 URL

확정:
- `/zapgoself`

### 2. 프로토타입을 운영용 랜딩으로 분리

해야 할 일:
- 프로토타입 전용 라벨 제거
- 공개 라우트 생성
- 프로토타입과 운영 버전의 공통 UI를 재사용 가능한 컴포넌트로 분리할지 결정
- 광고/대리점 유입 시 ref 또는 UTM 파라미터를 보존할 구조 마련

### 3. 주소 검색 실제 연동

결정 필요:
- 도로명주소 API와 카카오 주소 API 중 무엇을 쓸지

구현 필요:
- 주소 검색 모달을 실제 API 응답 기반으로 교체
- 선택 주소 저장
- 주소 검색 실패/미선택 상태 처리

### 4. 문자 발송 실제 연동

현재 상태:
- 기존 SMS API는 `phone + link`를 받아 발송 가능
- 새 퍼널은 서버 저장 세션 + 짧은 복원 토큰 방식으로 전환

추가 구현 필요:
- 새 퍼널용 링크 포맷 설계
- 선택 옵션/평형/창문 수/연락처/주소를 안전하게 복원할 저장소 구성
- 문자 재발송 UX 연결

확정:
- `/zapgoself?r={token}` 링크 사용
- 실제 개인정보는 `self_estimate_sessions`에 암호화 저장
- 복원 토큰만 문자 링크에 노출

### 5. 상담 신청 저장 연동

현재 상태:
- 기존 고객 저장 API는 사용 가능

추가 구현 필요:
- 새 퍼널의 입력값을 고객 저장 구조에 맞게 매핑
- 메모, 선택한 시공 방식, 보양, 창틀 모헤어, 방충 옵션을 notes 또는 별도 필드에 저장
- 상담 신청 성공 화면 구현

결정 필요:
- 이름 없이 저장하는 고객 레코드를 현재 관리자 화면에서 어떻게 보여줄지
- 문자 발송 시점과 상담 신청 시점의 리드를 같은 고객으로 볼지, 별도 레코드로 볼지

### 6. 실제 링크 연결

연결 필요:
- 카톡문의
- 전화문의
- 실제 시공 사례 영상

확정:
- 카카오채널 URL: `http://pf.kakao.com/_PjwDxj/chat`
- 대표 전화번호: `1600-9195`
- 시공 사례 영상 URL: `https://www.youtube.com/watch?v=_tq8gXHrhe4`

### 7. 법무/운영 확인

점검 필요:
- 개인정보 수집·이용 동의 문구
- 개인정보처리방침과 실제 수집 항목 일치 여부
- 문자 발송 내용과 운영 목적 적합성
- 리드 보관 기간

### 8. 공개 전 QA

필수 테스트:
- 모바일 화면 전 구간
- 주소 검색 성공/실패
- 문자 발송 성공/실패/재발송
- 문자 링크 복귀 후 옵션 복원
- 상담 신청 저장
- 관리자 화면 노출
- 중복 제출 방지
- 뒤로가기 흐름

## 다음에 사용자 확인이 필요한 결정

1. 공개 랜딩 URL
2. 주소 검색 API 선택
3. 문자 링크 복원 방식
4. 기존 고객 저장 구조와 새 리드 구조를 어떻게 연결할지

- 문자 링크 복원: 서버 저장 세션 + 짧은 토큰 방식
- 리드 저장: 문자 발송 시 생성한 고객 레코드를 상담 신청 단계에서 이어서 업데이트
